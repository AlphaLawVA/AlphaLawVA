# 법령 검색 평가셋 가이드라인 v0.1

## 1. 목적과 범위

이 평가셋은 AlphaLawVA의 법령 검색 단계에서 KURE-v1, BGE-M3,
`text-embedding-3-large`를 동일한 조건으로 비교하기 위한 골드 평가셋이다.

이 평가셋이 측정하는 질문은 하나다.

> 사용자 질문이 들어왔을 때 정답에 필요한 법령 청크를 상위 K개 안에서
> 얼마나 빠짐없이, 높은 순위로 검색하는가?

다음 항목은 이 평가셋의 범위가 아니다.

- 검색된 근거로 작성한 최종 답변의 정확성, 충실성, 표현 품질
- 답이 없을 때 답변을 거절하는 능력
- 권한, 승인, 부작용, 다중 턴, 프롬프트 인젝션 처리
- 툴 선택과 툴 호출 인자의 정확성

위 항목은 각각 답변 평가셋과 에이전트 통합 평가셋으로 분리한다.

## 2. 기본 원칙

1. 질문 문장보다 정답 라벨의 품질을 우선한다.
2. 정답은 키워드가 아니라 사람이 검수한 청크 ID와 관련도다.
3. 키워드는 Keyword Coverage를 위한 보조 진단값으로만 사용한다.
4. 세 모델에 같은 질문, 데이터 스냅숏, 청킹, K 값을 사용한다.
5. 모델 결과를 가린 상태에서 후보 청크를 판정한다.
6. 실제 사용자 질문을 우선하되, 출시 전에는 출처를 밝힌 합성 질문으로 시작한다.
7. 평가셋을 한 번에 완성하지 않고 파일럿, 확장, 회귀 순으로 키운다.
8. 실패 문항은 통과한 뒤에도 삭제하지 않는다.
9. 법령 데이터와 평가셋의 버전을 실행 결과에 함께 기록한다.
10. 평균 점수로 치명적인 검색 누락을 가리지 않는다.

## 3. 평가 단위

한 테스트 케이스는 다음 항목을 한 덩어리로 관리한다.

- 사용자 질문 1개
- 질문 유형, 법률 영역, 난이도, 치명 여부
- 질문 출처
- 보조 진단용 필수 개념
- 후보 청크별 관련도와 판정 근거
- 법령 데이터 스냅숏
- 작성 및 검수 상태

정확한 필드와 타입은
`data/statutes/evaluation/schema_v01.json`을 따른다.

## 4. 관련도 라벨

| 값 | 의미 | 판정 기준 |
|---:|---|---|
| 3 | 핵심 정답 | 질문의 핵심 요건, 효과 또는 절차를 직접 설명하는 조문 |
| 2 | 필수 보충 | 정확한 답변에 필요한 내용 일부를 제공하지만, 이 청크만으로 핵심 답변이 완성되지 않는 조문 |
| 1 | 참고 관련 | 같은 주제를 다루지만 질문에 필요한 법적 요건, 효과 또는 절차를 제공하지 않는 조문 |
| 0 | 오답 | 질문 해결에 쓰이지 않거나 혼동을 일으키는 조문 |

평가 시 관련도 2 이상을 정답으로 취급한다.

관련도 1과 2가 헷갈리면 다음 질문으로 구분한다.

> 이 청크가 빠질 때 질문에 대한 정확한 법적 설명에서 중요한 내용 하나가
> 실제로 빠지는가?

- 빠지면 2점 이상이다.
- 같은 주제일 뿐 답변 구성에 없어도 되면 1점 이하다.
- 단순히 같은 법률, 대상 또는 용어를 다룬다는 이유만으로 2점을 주지 않는다.
- 여러 조문이 함께 필요한 질문은 각 청크가 담당하는 필수 내용을 근거에
  명시한다.

- MRR: 관련도 2 이상인 첫 청크의 순위
- Recall@K: 상위 K에서 찾은 정답 청크 수 / 전체 정답 청크 수
- Hit@K: 상위 K에 정답 청크가 하나라도 있으면 1
- nDCG@K: 관련도 0~3과 검색 순위를 함께 반영
- Precision@K: 상위 K 중 관련도 2 이상인 청크의 비율

키워드가 처음 등장한 순위는 표준 MRR이 아니다. 별도로 계산한다면
`Keyword Coverage@K`처럼 이름을 구분한다.

## 5. 파일럿 50문항 분포

### 질문 유형

| 유형 | 코드 | 개수 |
|---|---|---:|
| 직접적인 조문·사실 질문 | `direct_fact` | 10 |
| 일상어·동의어로 바꾼 질문 | `natural_paraphrase` | 12 |
| 요건·기간·예외·단서 질문 | `condition_exception` | 10 |
| 여러 조문이 필요한 질문 | `multi_article` | 10 |
| 유사 조문을 구별해야 하는 질문 | `confusable_concept` | 8 |
| 합계 |  | 50 |

### 난이도

- 쉬움: 15개
- 보통: 25개
- 어려움: 10개

### 치명 문항

위 50문항 중 10개를 `critical: true`로 지정한다. 치명 문항은 별도
질문 유형이 아니며, 서비스 핵심 사용자 상황에서 반드시 검색되어야 하는
질문이다.

### 법률 영역

주택임대차, 매매·중개, 등기·권리, 건축·토지, 경매·집행 및 여러 영역을
함께 요구하는 질문을 포함한다. 최종 개수는 현재 코퍼스의 법령 구성과
AlphaLawVA의 우선 사용자 시나리오를 대조한 뒤 확정한다.

## 6. 질문 작성 규칙

1. 한 문항은 하나의 명확한 정보 요구를 가져야 한다.
2. 법령명을 모르는 일반 사용자가 입력할 법한 문장을 우선한다.
3. 정답 조문의 문장을 그대로 복사해 질문으로 만들지 않는다.
4. 조문 번호를 직접 묻는 문항은 `direct_fact` 일부에만 둔다.
5. 여러 조문이 필요하면 왜 여러 조문이 필요한지 목적에 적는다.
6. 질문 자체에 정답 키워드를 과도하게 노출하지 않는다.
7. 합성 질문은 `source.type`과 `source.synthetic`에 명시한다.
8. 공개 자료를 변형했다면 식별 가능한 출처를 `source.reference`에 남긴다.
9. 개인정보가 포함된 실제 로그는 비식별화 후 사용한다.
10. 답이 존재하지 않는 질문은 현재 검색 모델 비교에 섞지 않는다.
11. 같은 의도의 표현 변형은 최대 2개로 제한하고 같은 `variant_group`을 기록한다.
12. 표현 변형은 개별 점수와 시나리오 그룹 단위 점수를 함께 확인한다.

## 7. 정답 라벨링 절차

### 1차: 시드 정답 작성

작성자는 실제 법령 청크를 읽고 최소 한 개의 시드 정답을 지정한다.
시드 정답은 아직 완성된 골드 라벨이 아니다.

### 2차: 검색 결과 풀링

각 질문을 세 모델에서 동일한 설정으로 검색하고 각 Top-10 결과를 합친다.
가능하면 키워드 검색 결과도 후보 풀에 추가한다.

### 3차: 블라인드 판정

검수자는 어떤 모델이 검색했는지 모르는 상태에서 후보 청크에 관련도
0~3과 판정 근거를 부여한다. 질문마다 관련도 2 이상인 청크가 최소 한 개
있어야 한다.

### 4차: 교차 검수

작성자와 다른 사람이 다음 항목을 확인한다.

- 다른 법령의 정답 조문이 빠지지 않았는가
- 관련도 2와 3이 일관되게 구분됐는가
- 유사하지만 오답인 조문이 0 또는 1로 표시됐는가
- 질문이 모호하거나 정답을 과도하게 암시하지 않는가
- 현재 법령 스냅숏에서 유효한가

교차 검수를 통과한 문항만 `review.status: approved`로 변경한다.

교차 검수 인력이 제한된 파일럿에서는 다음 AI 보조 절차로 검수 대상을
줄일 수 있다.

1. 사람의 라벨을 보여주지 않은 원본 블라인드 후보 풀을 AI가 독립 판정한다.
2. 관련도 `2 이상/미만` 판정이 다른 후보를 모두 교차 검수 대상으로 삼는다.
3. AI 저확신 후보, 치명 문항의 양성·음성 통제표본을 추가한다.
4. 사람과 AI가 일치한 후보 중 10%를 고정 시드로 무작위 추출한다.
5. 팀원에게는 기존 사람·AI 라벨, 모델명, 검색 순위, 추출 사유를 공개하지
   않는다.

AI 판정은 검수 우선순위를 정하는 보조 자료일 뿐 골드 라벨이나 승인을
대체하지 않는다. 팀원 판정까지 불일치하면 해당 후보는 합의 전까지
미확정으로 두고 문항 상태를 `draft`로 유지한다.

법령 근거 재판정을 사용한 경우에도 결과는 사람의 최종 승인 전까지
`draft`다. 최종 승인자는 최소한 다음 항목을 확인한다.

- 질문 11건의 표현과 정보 요구
- 2점 이상으로 남은 모든 정답 청크
- 다수결과 법령 근거 재판정에서 정답 여부가 달라진 모든 청크
- 질문별 정답이 최소 1건이고, 핵심 근거 3점이 누락되지 않았는지

## 8. 평가 지표와 모델 선정 규칙

### 주 지표

- Recall@5
- Recall@10

### 순위 지표

- MRR@10
- nDCG@10

### 보조 지표

- Precision@10
- Hit@10
- Keyword Coverage@10
- 질의당 처리 시간과 전체 처리 시간

### 선정 우선순위

1. 치명 문항의 Top-10 누락 여부
2. 전체 Recall@10
3. nDCG@10
4. MRR@10
5. 비용, 속도, 운영 복잡도

외부에 정해진 절대 합격선이 있다고 가정하지 않는다. 파일럿 첫 실행을
기준선으로 저장한 뒤 팀이 합격선을 문서화한다. 다만 치명 문항은
`Top-10 누락 0건`을 우선 조건으로 사용한다.

모델 간 Recall@10 차이가 3%p 이내라면 동률 구간으로 보고 nDCG, MRR,
비용과 운영 편의성을 함께 검토한다. 이 규칙을 변경할 때는 변경 날짜,
담당자, 근거 평가셋과 실행 결과를 남긴다.

## 9. 데이터셋 생명주기

### v0.1: 50문항 파일럿

- 스키마와 질문 유형이 실제로 작동하는지 확인
- 라벨링 불일치와 누락 정답 발견
- 세 모델의 차이가 드러나는지 확인

### v1.0: 100문항 이상 골드 세트

- 파일럿 규칙을 고정한 뒤 영역과 난이도를 확장
- 모델 최종 선정에 사용
- 선정 결과를 본 뒤 문항이나 라벨을 유리하게 바꾸지 않음

### 회귀 세트

- 이전에 실패한 문항을 별도 파일에 누적
- 최초 실패 모델, 날짜, 실패 원인을 기록
- 통과한 뒤에도 삭제하지 않음

## 10. 버전과 실행 기록

모든 평가 실행에는 다음을 남긴다.

- 평가셋 버전과 SHA-256
- 법령 청크 스냅숏 SHA-256
- 청킹 전략 버전
- 임베딩 모델 이름과 revision
- 벡터 차원과 정규화 설정
- 검색 K와 거리 함수
- 실행 날짜와 실행자
- 지표와 질문별 순위
- 실패 문항 목록

평가셋 정의는 Git으로 관리한다. 실행 결과는 원본과 요약을 구분하고,
팀원이 재현할 수 있는 위치에 보관한다.

## 11. 금지 사항

- 키워드 존재만으로 정답 여부를 확정하지 않는다.
- 특정 모델이 잘 찾는 문장으로 질문을 고쳐 점수를 올리지 않는다.
- 모델마다 다른 평가셋이나 K를 사용하지 않는다.
- 답이 없는 질문을 일반 Recall 평균에 섞지 않는다.
- 평균 점수만 보고 치명 문항 실패를 무시하지 않는다.
- 법률 근거를 확인하지 않은 합성 질문을 승인 상태로 두지 않는다.
- 평가 결과에 맞춰 합격선을 사후에 낮추지 않는다.
- 실패한 문항을 삭제하거나 결과 이력을 덮어쓰지 않는다.

## 12. 문항 검수 체크리스트

- [ ] 질문의 정보 요구가 하나로 명확한가
- [ ] 질문 출처와 합성 여부가 기록됐는가
- [ ] 실제 청크를 읽고 시드 정답을 지정했는가
- [ ] 세 모델 Top-10 후보를 모두 판정했는가
- [ ] 관련도 2 이상인 정답이 최소 하나 있는가
- [ ] 관련도 0~3의 판정 근거가 적혀 있는가
- [ ] 다른 법령의 정답 조문 누락을 확인했는가
- [ ] 정답 키워드가 질문에 과도하게 노출되지 않았는가
- [ ] 현재 법령 스냅숏과 청크 ID가 기록됐는가
- [ ] 작성자와 다른 검수자가 승인했는가

## 13. 현재 실행 순서

1. 질문 11건, AI 초안 정답 청크 38건, 다수결과 정답 여부가 달라진
   42건의 사람 최종 검수를 완료했다.
2. 사람 검수에서 1건을 정답으로 복원해 39개 정답 청크를 확정하고,
   11문항의 상태를 `approved`로 변경했다.
3. 승인된 11문항을 그대로 유지한 채 같은 규칙으로 39문항을 추가한다.
4. 50문항 전체를 동일한 검색 및 검수 절차로 평가한다.
