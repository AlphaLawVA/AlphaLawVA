# RAG 검색·생성 모델 비교 요약

계약서 검토·특약 생성에 쓰는 법령 검색 설정과 생성 모델의 비교 기록이다.
결과는 후보 비교이며 최종 결정이 아니다(`docs/RAG_AND_EVALUATION.md`).
원본 결과는 `local_data/rag_eval/`(git 제외)에 있다.

## 1. 법령 검색 설정 비교 (완료, 호출 비용 없음)

- 도구: `python -m ml.evaluation.rag_eval.retrieval_eval --dataset <정답 jsonl> --device cpu`
- 데이터: 법령 검색 정답 50문항(`statute_retrieval_v01_50_approved.jsonl`), 관련도 2 이상을 정답으로 본다.
- 조건: BGE-M3, 청킹 `article_with_overflow_split_v01`, 후보 깊이 50, LLM 호출 0회.
- 검증: dense 수치(Recall@5 46.7%, Recall@10 61.5%, MRR 0.593)가 기존 승인 평가(`statute-50-v01-initial`)와 일치한다.
- 실행 기록: `local_data/rag_eval/retrieval/run-003/` (config.json, results.json, summary.md)

| 방식 | Recall@3 | Recall@5 | Recall@10 | nDCG@10 |
|---|---:|---:|---:|---:|
| **dense (현재 서비스)** | **37.3%** | **46.7%** | **61.5%** | **0.535** |
| RRF 하이브리드 (dense+BM25, `search_many_hybrid`) | 16.4% | 27.4% | 43.9% | 0.334 |
| RRF + 2-gram BM25 | 29.0% | 37.0% | 50.1% | 0.415 |
| 가중합 BM25 0.1 + 2-gram | 24.0% | 29.5% | 35.5% | 0.308 |
| 가중합 BM25 0.8 (논문 최적값) | 1.5% | 2.0% | 4.5% | 0.052 |
| BM25 단독 / 2-gram BM25 단독 | 1.5% / 13.2% | 2.0% / 18.1% | 4.5% / 25.5% | 0.052 / 0.211 |

dense 대비 차이는 모든 하이브리드·BM25 변형에서 95% 신뢰구간이 0 아래이다(질문 단위 bootstrap).

### 해석

- 이 데이터에서는 **dense 단독이 가장 높다.** 논문의 "BM25+dense가 최고"는 재현되지 않았다.
- BM25가 낮은 원인은 서비스 BM25가 공백 단위 단어를 토큰으로 쓰기 때문으로 보인다("전입신고를"과 "전입신고"가 다른 토큰). 글자 2-gram으로 바꾸면 Recall@10이 4.5%에서 25.5%로 오르지만 dense에는 못 미친다. 형태소 분석을 쓴 BM25는 아직 비교하지 않았다.
- 논문은 도메인·데이터(민사 판례 QA, 파인튜닝한 E5)가 달라 그대로 이식할 수 없다.
- 서비스 최소 유사도(0.35)는 이 50문항에서 아무것도 걸러내지 않는다(0.25·0.5도 동일, 빈 결과 0%). 다만 50문항이 모두 정상 질문이라 걸러지지 않는 것이 당연한 결과이므로, 이것만으로 장치가 작동하지 않는다고 판단할 수 없다. 무관한 질문(negative set)으로 별도 검증이 필요하다(2-11절 참고).
- 상위 3개에 앞뒤 청크를 붙이면 Recall이 37.3%에서 42.0%로 오르지만 컨텍스트가 평균 8.6개로 커진다.
- `search_many_hybrid`가 반환하는 유사도는 RRF 점수(약 0.03)라 서비스의 최소 유사도(0.35)를 그대로 쓰면 전부 걸러진다. 서비스가 하이브리드로 바뀔 때 함께 점검해야 한다.

### 한계

- 정답 50문항은 일반 사용자 질문 스타일이며 계약서 항목 질의와 분포가 다르다.
- 임베딩 선정에 쓴 같은 50문항이므로 가중치를 이 데이터에서 고르면 과적합한다. α 0.1·0.2는 탐색용이다.
- 법령 청크만 평가했다. 판례는 별도 비교가 필요하다.

### 2-3. 판정 교차 검증 (완료)

같은 출력을 다른 계열 판정자(`gpt-6.1-terra`)로 다시 채점했다.

| 대상 출력 | 판정 `gemini-3.8-flash` | 판정 `gpt-6.1-terra` |
|---|---:|---:|
| 기준선 faithfulness | 54.6% | 55.6% |
| 3.8 flash faithfulness | 71.7% (자기 채점) | 67.8% (다른 계열) |
| 기준선 relevancy | 71.3% | 86.1% |
| 3.8 flash relevancy | 89.3% (자기 채점) | 88.1% (다른 계열) |

- faithfulness는 두 판정자가 거의 같아(±4%p) 순위(기준선 < 3.8 flash)가 유지된다. 자기 채점 편향은 작았다.
- relevancy는 기준선에서 판정자 간 차이가 크다(71% 대 86%). relevancy는 판정자 의존이 커서 단독 근거로 쓰기 어렵다.

### 해석과 한계

- 지금까지 근거 충실도(faithfulness)는 flash-lite < 3.8 flash < terra 순이다. 가격은 비슷한 순서로 올라간다. 단, 25케이스이고 항목 수가 달라 평균의 분모가 다르다(18/15/16).
- 3.8 flash(7건)와 terra(5건)는 답을 생략한 항목이 있다. 생략된 항목은 대부분 검색 근거가 질문과 무관했다(예: 가압류 질의에 지방세기본법·국세징수법). 근거가 없을 때 억지로 답하지 않는 동작일 수 있으나, 원본 응답을 저장하지 않아 모델이 생략했는지 서버 검증이 걸렀는지는 확인하지 못했다.
- 개선 여지는 모델보다 검색·질의 품질(어색한 질의 문장 포함)에 더 크다.
- 3.8 flash는 `minimal` 사고 수준을 지원하지 않아 `low`로 실행했다. terra는 제공자 기본 추론 설정이다. 사고 수준이 달라 순수한 모델 차이만은 아니다.
- OpenAI 호출은 이 키에서 401이 간헐적으로 났다(약 25~30%, 과금 없음). 어댑터에 재시도를 넣었고 기록은 이어하기로 합쳤다.
- 판정 LLM 점수는 사람 표본 검토로 최종 확인해야 한다(`review_sheet.md`).
- Claude는 Sonnet 5.5만 비교했다. 경량(Haiku 5.5)은 요청에 따라 건너뛰었다. Sonnet은 스키마를 지시문으로 전달하는 방식이라 Gemini·OpenAI의 구조화 출력과 조건이 다르다.

- 고양이·바퀴벌레 같은 요청은 검색이 무관한 법령을 가져온다. 현재 규칙은 "근거 전체가 무관하면 항목을 출력하지 않음"이라 결과가 빌 수 있다. 근거가 약한 자연어 요청 처리가 다음 과제다.
- 25~32케이스이므로 작은 차이는 우연일 수 있다. 사람 표본 검토가 필요하다(`review_sheet.md`).

### 2-6. 근거가 없어도 초안 생성 (특약 v0.7, 분류기 v0.2)

배경: 고양이·바퀴벌레 방역 같은 요청은 검색이 무관한 법령을 가져와, 모델이 "근거 전체가 무관하면 출력하지 않음" 규칙대로 항목을 생략했다.

### 2-10. 리랭커 시험 (법령 검색 정답 50문항, CPU, LLM 호출 0회)

- 도구: `python -m ml.evaluation.rag_eval.rerank_eval --dataset <정답 jsonl> --reranker-path <모델 폴더>`
- 조건: BGE-M3 dense 후보 N개(10·20·30·50)를 크로스 인코더 리랭커로 재정렬해 상위 3개를 평가한다. 정답은 관련도 2 이상(질문당 평균 3.2개), 질문 단위 paired bootstrap으로 현재(dense) 대비 차이의 95% 신뢰구간을 구했다.
- 기준선: 현재 dense(Recall@3 37.3%, @5 46.7%, @10 61.5%), 대안 C(리랭커 없이 상위 10개 그대로 사용).
- 실행 기록: `local_data/rag_eval/rerank/run-001`(BAAI), `run-002-kure-nano`, `run-003-ko-public-admin`

| 모델 | Recall@3 (후보 10 / 20 / 30 / 50) | Recall@3 차이 95% 신뢰구간 (후보 20) | 쌍당 시간(CPU) | 용량 |
|---|---|---|---:|---:|
| 현재 (리랭커 없음) | 37.3% | — | — | — |
| `BAAI/bge-reranker-v2-m3` | 45.1 / 42.3 / 39.3 / 38.3% | [-2.1, +12.8] (0 포함) | 0.82초 | 2.27GB |
| **`nlpai-lab/KURE-Reranker-nano`** | **52.5 / 55.2 / 55.7 / 56.9%** | **[+9.5, +27.5]** | **0.36초** | **0.60GB** |
| `gimhae-geunamja/bge-reranker-v2-m3-ko-public-admin` | 43.2 / 44.1 / 42.7 / 41.2% | [-1.1, +15.0] (0 포함) | 0.80초 | 1.14GB |

- KURE-Reranker-nano만 모든 후보 수에서 신뢰구간이 0보다 크다(후보 10개 +15.1%p [+7.1, +24.0], 후보 50개 +19.5%p [+11.2, +28.2]). 상위 10개를 그대로 쓰는 방식(C)보다도 낫다(후보 20개 재정렬 시 상위 10개 Recall +10.2%p [+5.3, +16.3]).
- 원본 BAAI와 행정 특화 모델은 신뢰구간이 0을 포함해 효과가 불확실하다. 행정 문서·행정법 학습이 주택 임대차 법령 검색에는 도움이 되지 않았다.
- 속도(후보 수 기준 요청당 추가 시간 추정): nano는 후보 10개 약 3.6초, 20개 약 7.3초. GPU가 없는 노트북 CPU 기준이다.
- 주의: 행정 특화 모델은 bfloat16으로 저장돼 있어 CPU에서 그대로 올리면 매우 느려진다(80분 넘게 끝나지 않아 중단). float32로 올려야 하며 스크립트에 반영했다.
- 보완 정보: dense의 정답 포함 비율은 상위 3개에서 37.3%(1개라도 찾은 질문 70%), 상위 10개 61.5%(88%), 상위 50개 80.8%(98%)이다. 질문당 정답이 여러 개라 Recall@3이 낮게 보이는 면이 있고, 여러 조문에 걸친 질문이 가장 약하다(@3 18%, @10 34%).

**결론**: 리랭커 후보로 `KURE-Reranker-nano`를 잠정 확정한다. 후보 수는 10~20개가 현실적이다(후보 10개로 이득 대부분, 20개가 조금 더 높음).

**한계**
- 정답 50문항은 일반 질문 스타일이다. 특약 요청·검토 조항은 정답 라벨이 없어 수치로 확인하지 못했고, 재정렬 전후 상위 3개를 눈으로 본 확인에서는 좋아진 경우와 나빠진 경우가 섞여 있었다.
- 후보 수 네 가지를 살펴본 시험이라 가장 좋은 값을 고른 효과가 조금 섞일 수 있다.
- 코퍼스에 맞는 조문이 없는 요청(고양이, 바퀴벌레 등)은 리랭커로도 개선되지 않는다.
- 속도는 GPU 없는 CPU 기준이다.

**서비스 적용 전 필요**: 허용 가능한 추가 지연과 배포 환경(CPU·GPU) 합의, 특약·검토 스타일의 추가 확인.

### 2-11. 법령 최소 유사도 검증 (무관한 질문 포함, 법령 검색만, LLM 호출 0회)

- 배경: 서비스 법령 최소 유사도 0.35는 근거 없이 처음 연결할 때 잡은 기본값이다. 50문항이 모두 정상 질문이라 효과를 알 수 없었다.
- 방법: 질문 그룹별로 가장 비슷한 조문의 유사도(top1)를 비교했다. 정상 질문 80개(일반 질문 50, 특약 요청 14, 검토 조항·등본 16)와 무관 질문 20개(완전 무관 10, 법 얘기지만 부동산 아님 10, 직접 작성한 합성 질문).

| 질문 그룹 | 개수 | top1 유사도 최소 / 중앙 / 최대 |
|---|---:|---|
| 정상: 일반 질문 | 50 | 0.56 / 0.64 / 0.75 |
| 정상: 특약 요청 | 14 | 0.44 / 0.60 / 0.67 |
| 정상: 검토 조항·등본 | 16 | 0.57 / 0.61 / 0.73 |
| 무관: 완전 무관 (요리·날씨 등) | 10 | 0.36 / 0.41 / 0.47 |
| 무관: 법 얘기지만 부동산 아님 | 10 | 0.51 / 0.57 / 0.69 |

| 하한선 | 정답 조문 보존 | 정상 질문 빈 결과 | 무관 질문 빈 결과 |
|---:|---:|---:|---:|
| 0.35 (현재) | 100% | 0/80 | 0/20 |
| 0.45 | 100% | 1/80 | 8/20 |
| 0.50 | 100% | 2/80 | 10/20 |
| 0.55 | 98.6% | 3/80 | 13/20 |
| 0.60 | 88.6% | 17/80 | 19/20 |

- 0.35는 요리·날씨 같은 완전 무관 질문도 모두 통과시킨다(top1 0.36~0.47). 0.5로 올리면 완전 무관 질문이 모두 걸러지고 정답 조문은 잃지 않았다. 대가로 정상 질문 2개("고양이 두 마리", "바퀴벌레 세스코")가 근거 없이 처리된다. 이 요청들은 원래 맞는 조문이 코퍼스에 없다.
- 법 얘기지만 부동산이 아닌 질문(0.51~0.69)은 정상 질문과 점수가 겹쳐 하한선으로 가를 수 없다. 이런 입력은 분류기(범위 판단)의 몫이다.
- 하한선은 관련 조문과 무관한 조문을 가르지 못한다. 정답 조문 유사도 중앙값 0.64, 비정답 0.62로 거의 겹친다. 0.6 이상으로 올리면 정답을 11% 이상 잃는다. 즉 하한선은 품질 필터가 아니라 "근거가 아예 없음"을 알아차리는 느슨한 안전 바닥이다.
- 유사도의 의미는 임베딩 모델마다 달라, 일반적인 기준(0.5 보통, 0.7 매우 유사)을 그대로 쓸 수 없다. 우리 데이터에서 관련 조문의 최저 점수대 바로 아래에 바닥을 두는 것이 원칙이다.
- 한계: 무관 질문 20개는 직접 작성한 소량이고, 법령만 확인했다. 판례 하한선(0.2)은 확인하지 않았다.
- 결정: 0.5로 올릴 수 있는 근거는 있으나, 개선 효과가 작고 후보를 넓게 모으는 구조와 맞지 않아 아직 적용하지 않았다(팀 협의 중).

### 2-12. 서비스 입력 스타일(특약 요청·검토 조항)에서 리랭커 재검증 (AI 판정 정답 세트)

- 배경: 2-10절의 정답 50문항은 일반 질문 스타일이라, 서비스 입력과 같은 스타일의 효과를 따로 확인했다.
- 방법: `cases_v02`의 특약 요청·검토 조항 30질문(프롬프트 주입 시험 제외)에 대해 질문별 후보 풀을 만들었다(dense 상위 20 + KURE-nano 재정렬 상위 10, 합계 670건, 순서를 섞어 방식 정보를 숨김). `gpt-6.1-terra`가 기존 법령 관련도 지침(`statute-relevance-v0.1`)으로 질문별 판정했다(30회 호출, 총 $0.587). 관련도 2 이상을 정답으로 본다. 판정 분포는 0점 376 / 1점 224 / 2점 49 / 3점 21이다.
- 도구: `rag_eval/build_style_pool.py`(후보 풀), `rag_eval/judge_style_pool.py`(AI 판정). 실행 기록: `local_data/rag_eval/style_gold/`
- 정답이 0개인 7질문(특약 요청 5: 위약금·수리비·고양이·보일러 수리·바퀴벌레, 검토 조항 2: 원상복구 범위·소유권이전청구권가등기)은 후보 안에 관련 조문이 없어 평가에서 제외했다.

| 대상 | 질문 수 | 조건 | Recall@3 | Recall@5 | Recall@10 | nDCG@10 |
|---|---:|---|---:|---:|---:|---:|
| 전체 | 23 | dense | 34.7% | 42.8% | 58.7% | 0.544 |
| | | **nano 재정렬** | **55.2%** | **71.6%** | **90.1%** | **0.735** |
| 검토 조항 | 14 | dense → nano | 32.1% → 53.8% | 38.2% → 64.0% | 60.7% → 87.3% | 0.555 → 0.795 |
| 특약 요청 | 9 | dense → nano | 38.9% → 57.4% | 50.0% → 83.3% | 55.6% → 94.4% | 0.528 → 0.643 |

- Recall@3 차이(nano − dense, 95% 신뢰구간): 전체 +20.4%p [+6.9, +34.1], 검토 조항 +21.7%p [+7.6, +38.7], 특약 요청 +18.5%p [-3.7, +44.4](0 포함, 표본 9개).
- 검토 조항은 첫 정답 순위(MRR)가 0.564에서 0.929로 올랐고 질문의 100%가 상위 3개에 정답을 하나 이상 포함했다. 특약 요청은 Recall@5 +33.3%p [+11.1, +61.1]는 확실하지만 MRR은 0.472에서 0.423으로 약간 내려갔다.
- 정답 기준을 1점 이상으로 후하게 보면 평가 29질문에서 Recall@3이 19.7%에서 24.5%로(+4.8%p [+0.2, +9.3]), Recall@10이 48.7%에서 69.0%로 올라 방향은 같다. 정답이 질문당 많아져 Recall@3의 상한이 낮아지는 영향이 있다.
- 특약 요청 14건 중 5건은 후보 안에 정답이 없었다. 코퍼스에 맞는 조문이 없거나 검색 질의가 맞지 않는 문제로 리랭커로는 해결되지 않는다.

**사람 확인(20건, 비전문가 직관)**: AI가 2~3점을 준 10건 중 사람이 "이상함"이라 본 것은 0건(맞음 7, 모르겠음 3). AI가 0점인 3건은 모두 "이상함"으로 일치했다. AI가 1점("주제만 관련, 답에 꼭 필요하진 않음")을 준 7건 중 5건을 사람은 "관련 있어 보임"으로 봤는데, 정반대 판단이 아니라 같은 의미를 후하게 본 기준 차이다. 즉 AI는 사람보다 엄격했고 엉뚱한 조문을 정답으로 준 흔적은 없었다.

**한계**
- 정답은 AI 판정이며 사람은 20건만 직관으로 확인했다. 확정 라벨이 아니라 참고용 점검이다.
- 후보 풀에 nano의 상위 10개가 포함돼 nano에 유리한 편향이 조금 있을 수 있다(dense 상위 20도 함께 넣어 완화).
- 평가 질문이 23개이고 특약 요청은 9개뿐이라 신뢰구간이 넓다.
- 이 키는 OpenAI Responses API 권한(`api.responses.write`)이 없어 판정을 Chat Completions로 호출했다. 서비스에 OpenAI를 붙일 때 같은 제약을 고려해야 한다.
