# RAG 검색·생성 모델 비교 요약

계약서 검토·특약 생성에 쓰는 법령 검색 설정과 생성 모델의 비교 기록이다.
결과는 후보 비교이며 최종 결정이 아니다(`docs/RAG_AND_EVALUATION.md`).
원본 결과는 `local_data/rag_eval/`(git 제외)에 있다.

## 1. 법령 검색 설정 비교 (완료, 호출 비용 없음)

- 도구: `python -m ml.evaluation.rag_eval.retrieval_eval --dataset <정답 jsonl> --device cpu`
- 데이터: 법령 검색 정답 50문항(`statute_retrieval_v01_50_approved.jsonl`), 관련도 2 이상을 정답으로 본다.
- 조건: BGE-M3, 청킹 `article_with_overflow_split_v01`, 후보 깊이 50, LLM 호출 0회.
- 검증: dense 수치(Recall@5 46.7%, Recall@10 61.5%, MRR 0.593)가 기존 승인 평가(`statute-50-v01-initial`)와 일치한다.
- 실행 기록: `local_data/rag_eval/retrieval/run-003/` (config.json, results.json, summary.md)

| 방식 | Recall@3 | Recall@5 | Recall@10 | nDCG@10 |
|---|---:|---:|---:|---:|
| **dense (현재 서비스)** | **37.3%** | **46.7%** | **61.5%** | **0.535** |
| RRF 하이브리드 (dense+BM25, `search_many_hybrid`) | 16.4% | 27.4% | 43.9% | 0.334 |
| RRF + 2-gram BM25 | 29.0% | 37.0% | 50.1% | 0.415 |
| 가중합 BM25 0.1 + 2-gram | 24.0% | 29.5% | 35.5% | 0.308 |
| 가중합 BM25 0.8 (논문 최적값) | 1.5% | 2.0% | 4.5% | 0.052 |
| BM25 단독 / 2-gram BM25 단독 | 1.5% / 13.2% | 2.0% / 18.1% | 4.5% / 25.5% | 0.052 / 0.211 |

dense 대비 차이는 모든 하이브리드·BM25 변형에서 95% 신뢰구간이 0 아래이다(질문 단위 bootstrap).

### 해석

- 이 데이터에서는 **dense 단독이 가장 높다.** 논문의 "BM25+dense가 최고"는 재현되지 않았다.
- BM25가 낮은 원인은 서비스 BM25가 공백 단위 단어를 토큰으로 쓰기 때문으로 보인다("전입신고를"과 "전입신고"가 다른 토큰). 글자 2-gram으로 바꾸면 Recall@10이 4.5%에서 25.5%로 오르지만 dense에는 못 미친다. 형태소 분석을 쓴 BM25는 아직 비교하지 않았다.
- 논문은 도메인·데이터(민사 판례 QA, 파인튜닝한 E5)가 달라 그대로 이식할 수 없다.
- 서비스 최소 유사도(0.35)는 이 50문항에서 **아무것도 걸러내지 않는다**(0.25·0.5도 동일, 빈 결과 0%). 근거가 약한 질문에서 "근거 없음"으로 빠지는 장치는 사실상 작동하지 않을 수 있다. 무관한 질문(negative set)으로 별도 검증이 필요하다.
- 상위 3개에 앞뒤 청크를 붙이면 Recall이 37.3%에서 42.0%로 오르지만 컨텍스트가 평균 8.6개로 커진다.
- `search_many_hybrid`가 반환하는 유사도는 RRF 점수(약 0.03)라 서비스의 최소 유사도(0.35)를 그대로 쓰면 전부 걸러진다. 서비스가 하이브리드로 바뀔 때 함께 점검해야 한다.

### 한계

- 정답 50문항은 일반 사용자 질문 스타일이며 계약서 항목 질의와 분포가 다르다.
- 임베딩 선정에 쓴 같은 50문항이므로 가중치를 이 데이터에서 고르면 과적합한다. α 0.1·0.2는 탐색용이다.
- 법령 청크만 평가했다. 판례는 별도 비교가 필요하다.

### 2-3. 판정 교차 검증 (완료)

같은 출력을 다른 계열 판정자(`gpt-6.1-terra`)로 다시 채점했다.

| 대상 출력 | 판정 `gemini-3.8-flash` | 판정 `gpt-6.1-terra` |
|---|---:|---:|
| 기준선 faithfulness | 54.6% | 55.6% |
| 3.8 flash faithfulness | 71.7% (자기 채점) | 67.8% (다른 계열) |
| 기준선 relevancy | 71.3% | 86.1% |
| 3.8 flash relevancy | 89.3% (자기 채점) | 88.1% (다른 계열) |

- faithfulness는 두 판정자가 거의 같아(±4%p) 순위(기준선 < 3.8 flash)가 유지된다. 자기 채점 편향은 작았다.
- relevancy는 기준선에서 판정자 간 차이가 크다(71% 대 86%). relevancy는 판정자 의존이 커서 단독 근거로 쓰기 어렵다.

### 해석과 한계

- 지금까지 근거 충실도(faithfulness)는 flash-lite < 3.8 flash < terra 순이다. 가격은 비슷한 순서로 올라간다. 단, 25케이스이고 항목 수가 달라 평균의 분모가 다르다(18/15/16).
- 3.8 flash(7건)와 terra(5건)는 답을 생략한 항목이 있다. 생략된 항목은 대부분 검색 근거가 질문과 무관했다(예: 가압류 질의에 지방세기본법·국세징수법). 근거가 없을 때 억지로 답하지 않는 동작일 수 있으나, 원본 응답을 저장하지 않아 모델이 생략했는지 서버 검증이 걸렀는지는 확인하지 못했다.
- 개선 여지는 모델보다 검색·질의 품질(어색한 질의 문장 포함)에 더 크다.
- 3.8 flash는 `minimal` 사고 수준을 지원하지 않아 `low`로 실행했다. terra는 제공자 기본 추론 설정이다. 사고 수준이 달라 순수한 모델 차이만은 아니다.
- OpenAI 호출은 이 키에서 401이 간헐적으로 났다(약 25~30%, 과금 없음). 어댑터에 재시도를 넣었고 기록은 이어하기로 합쳤다.
- 판정 LLM 점수는 사람 표본 검토로 최종 확인해야 한다(`review_sheet.md`).
- Claude는 Sonnet 5.5만 비교했다. 경량(Haiku 5.5)은 요청에 따라 건너뛰었다. Sonnet은 스키마를 지시문으로 전달하는 방식이라 Gemini·OpenAI의 구조화 출력과 조건이 다르다.

- 고양이·바퀴벌레 같은 요청은 검색이 무관한 법령을 가져온다. 현재 규칙은 "근거 전체가 무관하면 항목을 출력하지 않음"이라 결과가 빌 수 있다. 근거가 약한 자연어 요청 처리가 다음 과제다.
- 25~32케이스이므로 작은 차이는 우연일 수 있다. 사람 표본 검토가 필요하다(`review_sheet.md`).

### 2-6. 근거가 없어도 초안 생성 (특약 v0.7, 분류기 v0.2)

배경: 고양이·바퀴벌레 방역 같은 요청은 검색이 무관한 법령을 가져와, 모델이 "근거 전체가 무관하면 출력하지 않음" 규칙대로 항목을 생략했다.
변경: 분류기를 통과한 요청은 근거가 없거나 무관해도 초안을 만든다(`evidence_source_ids` 빈 배열 허용, 근거 없는 요청도 모델에 전달, 근거가 없으면 strategy에 그 사실을 밝힘). 조문·판례·법적 효과 인용 금지 규칙은 유지했다.

**분류기 (`scope_cases_v02`, 32개, flash-lite)**

| 프롬프트 | 정답 | 비고 |
|---|---:|---|
| v0.1 | 28/32 | 고양이 요청이 "정보 부족"으로 분류됨 |
| v0.2 | 30/32 | 생활 조건 특약(반려동물·방역·소음 등)을 범위 안으로, 애매하면 범위 안으로. 남은 오류: 모순 요청(범위 안으로 통과, 생성 단계에서 질문 처리)과 섞인 요청 |

v0.2에 짧은 주제 요청 규칙 한 줄을 추가하며 같은 케이스로 한 번 더 평가했다(조정에 쓴 케이스라 수치는 낙관적일 수 있음).

**특약 14건 재평가 (판례 포함 검색 근거, 판정 gemini-3.8-flash)**

| 지표 | gemini-3.5-flash-lite | gpt-6.1-terra |
|---|---:|---:|
| 항목 반환 | 15/15 | 15/15 |
| 규칙 실패·경고 | 실패 1 / 경고 5 | **실패 0 / 경고 0** |
| faithfulness | 23.1% | **75.0%** |
| 고양이·방역 요청 | 둘 다 초안 생성 | 둘 다 초안 생성 |
| 근거를 비운 상태(고양이·방역·시설 수리) | - | 3건 모두 초안 생성, 근거 인용 0, 지어낸 조문 없음 |

- 이전(v0.6, 같은 요청)에는 고양이·방역이 두 모델 모두 비어 있었다. 이제 두 모델 모두 초안을 만든다.
- 근거가 없을 때 terra는 "직접 근거가 되는 법령은 찾지 못해 당사자 합의 사항으로 작성했습니다"를 전략에 밝힌다.
- flash-lite는 faithfulness가 낮고, 일부 출력에서 단어 오류("분쟁"을 "분비"로 씀)가 보였다.
- 한계: 판정기는 "분쟁을 예방하기 위해서입니다" 같은 목적 설명도 주장으로 세어 근거 없음으로 판정한다. 합의 사항 특약의 faithfulness는 의미가 약하므로 사람 검토가 필요하다.
- 14건이라 작은 차이는 우연일 수 있다. OpenAI 호출이 네트워크 전환 중 끊겨 어댑터에 연결 끊김 재시도를 추가했다.

### 2-7. 응답 속도 (특약 생성 1건, 모델당 10회 순차 호출)

도구: `python -m ml.evaluation.rag_eval.latency_eval` (같은 요청·같은 근거로 반복, 호출 시간만 측정). 기록: `local_data/rag_eval/latency/run-001/`

| 모델 | 중앙값 | 느린 쪽 p95 | 평균 출력 토큰 | 출력 속도(토큰/초) | 오류 |
|---|---:|---:|---:|---:|---:|
| gemini-3.5-flash-lite | **2.3초** | 2.6초 | 336 | 146 | 0 |
| gemini-3.8-flash | 5.3초 | 6.1초 | 398 | 73 | 0 |
| gpt-6.1-terra | 7.0초 | 8.0초 | 455 | 65 | 0 |

- terra는 flash-lite의 약 3배, 3.8 flash의 약 1.3배 느리다. 호출 간 편차는 작다(최소~최대 6.1~8.0초).
- 측정은 요청 1건 기준이다. 요청이 여러 개면 한 번의 호출에서 출력이 길어져 시간이 더 걸린다. 서비스 전체 응답 시간에는 분류기 호출(약 1초)과 재작성 노드 호출이 더해진다.
- 네트워크 상태(와이파이·핫스팟)에 따라 절대값은 달라지므로 같은 환경에서의 상대값으로 본다.
- 이전 보고에서 terra 호출을 "10~20초"로 적었던 것은 판정 호출이 섞인 평가 실행 시간을 본 추정이었고, 직접 잰 값은 약 7초이다.

### 2-8. 요청 의도 보존 (특약 프롬프트 v0.9, 로컬 요청 4건)

배경: flash-lite가 "고양이를 키우고 싶다"를 "임대인의 동의 하에 사육할 수 있다"로 바꾸는 등, 요청의 핵심(허용·조건·범위)을 임의로 약화했다.
변경: 프롬프트 규칙 추가 - 핵심 내용(허용·금지, 부담 주체, 권리·의무 방향, 적용 조건과 범위)을 바꾸거나 약하게 만들지 않고, 영향을 줄 조건은 초안에 넣지 말고 확인 질문으로 남긴다.
같은 4개 요청(고양이, 시설 수리, 보증 가입 거절, 바퀴벌레 방역)을 실제 검색 근거로 생성(단일 실행, 판정 없이 출력을 직접 읽음).

| 요청 | flash-lite (v0.9) | gpt-6.1-terra (v0.9) |
|---|---|---|
| 고양이 두 마리 | 실행에 따라 다름: "사육할 수 있다"(의도 유지)와 "임대인의 동의를 받아"(약화)가 번갈아 나옴 | "허용한다" - 유지 |
| 보증 가입 거절 | 조건을 좁힘("임대인의 사유 또는 주택의 하자로", "임차인의 책임 없는 사유로") | "가입이 거절되면" - 유지 |
| 바퀴벌레 방역 | 실행에 따라 조건 추가("임차인의 과실이 아닌 경우") | "나오면 임대인은 세스코를 불러" - 유지 |
| 시설 수리 | 유지 | 유지 |

- terra는 4건 모두 요청 의도를 유지하고 부수 조건을 확인 질문으로만 남겼다. flash-lite는 같은 규칙에서도 실행마다 달라져, 프롬프트만으로 통제하기 어렵다.
- 한계: 4건, 단일 실행, 자동 채점 없음(직접 읽음). 의도 보존을 자동으로 재는 규칙은 아직 없다. 더 큰 케이스와 사람 검토로 확인이 필요하다.

### 2-9. 생성 모델 잠정 결론 (2026-11-11)

- 계약서 검토·특약 생성의 후보는 `gpt-6.1-terra`로 기운다. 측정상 terra가 우세했고(faithfulness 88.7% 대 79.3%, 근거 없는 주장 5건 대 22건, 비용 $0.22 대 $0.84), 일부 사람 검토에서도 품질 차이는 크지 않았다.
- 표본은 더 늘리지 않기로 했다(팀 회의 결정). 32항목이라 작은 차이는 우연일 수 있고, 사람 검토는 일부만 했다. 확정이 아니라 잠정 결론이다.
- 출력 길이는 Sonnet이 terra보다 대략 1.5배 길었다. 길이는 프롬프트로 조절할 수 있어 선택의 근거로 삼지 않았다.
- 내용증명 등 다른 기능은 이 비교에 포함되지 않았고 따로 평가한다.
- 서비스 적용 전 필요: 개인정보 합의, 키 관리, 재시도, 장애 시 Gemini 대체.
