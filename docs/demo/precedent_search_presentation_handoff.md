# 판례 검색 발표용 프론트 전달 데이터

## 1. 사용 목적

- 수요일 발표에서 판례 검색 전체 흐름을 더미데이터로 시연하기 위한 자료다.
- 판례의 사건번호, 법원, 선고일, 판례일련번호, 요약, 검색 청크, 전문은 AlphaLawVA 로컬 데이터와 실제 BGE-M3 검색 결과를 사용했다.
- `내 상황과 비교하기` 문장만 실제 배포 모델이 생성해야 할 목표 결과를 발표용으로 작성했다.
- 사건명, 검색 순위, 유사도 점수, 판례일련번호, 판시사항, 판결요지, 참조조문, 참조판례는 사용자 화면에 표시하지 않는다.

## 2. 발표 시나리오

### 최종 검색 질문

> 전세계약이 끝났는데 집주인이 보증금을 돌려주지 않습니다.

### 입력 적합성 분기

- 판정: `ALLOW`
- 판단 이유: 부동산 관계인 전세계약과 발생한 분쟁인 계약 종료 후 보증금 미반환이 함께 드러난다.
- 발표 처리: Gemini 호출 장면은 생략하고 `ALLOW` 성공 상태를 고정한다.
- 주의: 판단 이유는 발표 설명용이며 현재 판례 검색 공개 응답 필드가 아니다.

### 발표용 상태 식별자

- `search_id`: `00000000-0000-4000-8000-000000000001`
- `status`: `completed`
- `result_count`: `4`
- 위 식별자는 발표용 UI 상태를 연결하기 위한 값이며 판례 원본 정보가 아니다.

## 3. 화면 흐름과 버튼 동작

1. 예시 질문을 누르면 검색창에 질문만 입력한다. 자동 검색하지 않는다.
2. `검색`을 누르면 같은 화면의 검색창 아래에 판례 4건을 세로 목록으로 표시한다.
3. 목록의 `판례 전문 ↗`은 AlphaLawVA가 보유한 원문 모달을 연다.
4. 목록의 `상세보기 →`는 검색 질문의 맥락을 유지한 판례 상세 화면으로 이동한다.
5. 별 버튼은 즐겨찾기를 켜거나 끈다.
6. 상세 화면의 `내 상황과 비교하기`를 누르면 로딩 후 `matched_reason` 한 문단을 표시한다.
7. `이 판례가 검색된 근거 보기`를 펼치면 실제 매칭 청크를 세로로 표시한다.
8. `검색 근거 표시` 스위치는 기본 ON이다. 끄면 요약·근거 청크·전문에서 `#fffbe8` 배경 강조만 사라진다. 검색이나 비교 생성을 다시 실행하지 않는다.
9. `판례 전문 보기`는 내부 원문 모달을 열고, `국가법령정보센터 공식 원문 보기 ↗`는 외부 새 탭을 연다.
10. 검색 결과로 돌아가도 질문, 결과 목록, 즐겨찾기, 비교 생성 결과를 유지한다.

## 4. 검색 결과 목록

사용자 화면에는 다음 값만 표시한다.

- 작은 보조정보: 법원명 · 선고일 · 판결유형
- 큰 제목: 사건번호
- 본문: 쉬운요약 미리보기
- 버튼: `판례 전문 ↗`, `상세보기 →`, 별 모양 즐겨찾기

> 이 사건 임대차계약은 2004. 8. 17. 종료하였는데, 원고는 그 후 10년간 이 사건 임대차보증금반환채권을 행사하지 않았으므로, 이 사건 임대차보증금반환채권은 시효로 소멸하였다.\

- 사용자 노출 필드: `matched_reason`
- 값의 출처: 발표 목표 품질을 위해 작성한 생성값

#### 실제 검색 청크

청크 1 · 이유

> 적물을 점유하는 동안 위 규정에 따라 법정임대차관계가 유지되고 있는데도 임차인의 보증금반환채권은 그대로 시효가 진행하여 소멸할 수 있다고 한다면, 이는 위 규정의 입법 취지를 훼손하는 결과를 가져오게 되어 부당하다.\
> 위와 같은 소멸시효 제도의 존재 이유와 취지, 임대차기간이 끝난 후 보증금반환채권에 관계되는 당사자 사이의 이익형량, 주택임대차보호법 제4조 제2항의 입법 취지 등을 종합하면, 주택임대차보호법에 따른 임대차에서 그 기간이 끝난 후 임차인이 보증금을 반환받기 위해 목적물을 점유하고 있는 경우 보증금반환채권에 대한 소멸시효는 진행하지 않는다고 보아야 한다.\
> 나. 원심판결 이유와 기록에 따르면 다음 사실을 알 수 있다.\
> (1) 소외 1은 피고(반소원고, 이하 ‘피고’라 한다)로부터 임대권한을 위임받아 1998. 5. 31. 피고를 임대인으로 하여 이 사건 102호를 원고에게 임대하였다. 원고는 그 무렵 피고에게 임대차보증금 2,500만 원을 지급하고 이 사건 102호에 입주하였다.\
> (2) 이 사건 임대차계약에 따른 임대차기간이 끝날 무렵 피고는 원고에게 이 사건 102호를 인도해 달라고 요구하였으나 원고는 보증금의 반환을 요구하면서 인도를 거부하였고, 임대차기간이 만료된 2000. 5. 30. 이후에도 이 사건 102호에 계속 거주하였다.\
> (3) 원고는 2008. 5.경 결혼을 하면서 이 사건 102호에 기본적인 가재도구를 남겨둔 채 2013년 무렵까지 우편물 정리와 집기류 확인 등을 위해 원고의 모친 소외 2 등으로 하여금 이 사건 102호에 출입하게 하면서 점유하였다.

`적물을`로 시작하는 것은 문서 작성 중 생긴 오탈자가 아니라 실제 저장된 검색 청크의 시작 지점이다. 발표 화면에서도 청크를 임의로 고치거나 전문처럼 이어 붙이지 않는다.

## 6. 비교하기 상태와 고정 안내

### 버튼을 누르기 전

- `status`: `not_generated`
- 버튼 문구: `내 상황과 비교하기`
- 비교 결과 영역은 표시하지 않는다.

### 생성 중

- `status`: `generating`
- 문구: `사용자 상황과 판례를 비교하고 있습니다.`
- 버튼은 중복 클릭되지 않게 비활성화한다.

### 생성 성공

- `status`: `generated`
- 위 판례별 `matched_reason`을 표시한다.
- 같은 검색 결과나 즐겨찾기 상세를 다시 열면 저장된 결과를 재사용한다.

### 생성 실패

- `status`: `failed`
- 문구: `비교 결과를 만들지 못했습니다. 잠시 후 다시 시도해 주세요.`
- `다시 시도` 버튼을 제공한다.

### 프론트 고정 안내

> 이 비교는 참고용이며 같은 결과를 보장하지 않습니다. 구체적인 판단은 법률 전문가와 상담하세요.

이 안내는 모델 생성값이 아니라 프론트 고정 문구다.

## 8. 판례 전문 보기

전문 원문은 `docs/demo/precedent_search_full_texts.json`에 저장했다.

- 모달 큰 제목: 사건번호
- 보조정보: 법원명 · 선고일 · 판결유형
- 안내: `보유 중인 판례 데이터로 제공하는 전문입니다.`
- 본문 순서: 주문 → 청구취지 → 원심판결 → 이유
- 비어 있는 항목은 제목까지 생략한다.
- 검색 청크와 겹치는 전문 영역은 `검색 근거 표시`가 ON일 때 `#fffbe8`로 강조한다.
- 사건명과 판례일련번호는 화면에 표시하지 않는다.

## 9. 값의 출처

| 값 | 출처 | 사용자 화면 |
|---|---|---|
| 사건번호·법원명·선고일·판결유형 | `final_cases` DB | 표시 |
| 판례요약·쉬운요약 | `final_cases`의 생성 요약 데이터 | 표시 |
| 검색 청크 | BGE-M3 + ChromaDB 실제 검색 결과 | 상세에서 접어 표시 |

### 검증 기준

- 검색 질문은 로컬 BGE-M3와 `precedents_bge-m3_v1` ChromaDB에 실제로 실행했다.
- 판례 4건은 실제 검색 결과 중 질문과 직접 관련된 판례를 선별했다.
- 검색 청크는 검색기가 반환한 문자열을 수정하지 않고 기록했다.
- 전문 JSON은 `local_data/precedents/processed/final_cases/{판례일련번호}.json`의 `주문·청구취지·원심판결·이유`를 그대로 추출했다.
- JSON 생성 후 네 필드를 원본 `final_cases`와 다시 비교한다. 빈 필드는 JSON에서 생략한다.
- 국가법령정보센터에서 네 사건의 사건번호, 법원, 선고일을 확인했다.
