# 판례 BM25·Weighted RRF 하이브리드 90문항 비교

## 결론

현재 판례 검색에는 BM25 하이브리드를 도입하지 않고 `BGE-M3 Dense → KURE
nano` 흐름을 유지한다. BM25 단독은 Dense보다 모든 품질 지표가 낮았고, BM25가
후보군을 실제로 바꾸는 0.5/0.5 하이브리드도 Recall@20이 0.714527에서
0.669797로 하락했다.

Dense 비중이 0.7 이상인 하이브리드는 MRR@20과 nDCG@20을 일부 개선했지만,
90문항 모두에서 Dense와 동일한 판례 20건을 반환하고 순서만 바꿨다. 다음 단계의
KURE가 같은 후보 20건을 다시 전부 리랭킹하므로 후보 보완 효과가 없다. 따라서
새 청크 라벨링과 20문항 KURE 후속 평가는 진행하지 않는다.

## 실험 흐름

```text
골든셋 90문항·549개 라벨 고정
→ 동일한 BGE-M3 ChromaDB 24,267청크 사용
→ Dense Top20과 Kiwi BM25 Top20 검색
→ Weighted RRF로 0.9/0.1, 0.8/0.2, 0.7/0.3, 0.5/0.5 생성
→ Recall@20·MRR@20·nDCG@20·Precision@20·Hit@20 비교
→ Dense가 놓친 골드 복구와 Dense 골드 손실을 질문별 비교
```

Dense와 BM25의 원점수 범위가 다르므로 원점수 가중합은 사용하지 않았다. RRF
상수는 60, BM25는 `k1=1.5`, `b=0.75`를 사용했다. BM25 토큰은 Kiwi에서
명사·용언·수식언·어근·외국어·숫자 등 내용 형태소만 남겼다.

## 판단과 후속 작업

- 생산 판례 검색에는 BM25 또는 Weighted RRF를 적용하지 않는다.
- 현재 `BGE-M3 Dense → KURE nano` 후보 검색·리랭킹 구조를 유지한다.
- BM25가 추가한 후보의 수동 라벨링과 KURE 후속 평가는 생략한다.
- 향후 사건번호·법률용어 정확 일치 질의를 별도 라우팅할 필요가 생기면, 전체
  하이브리드가 아니라 조건부 lexical fallback으로 다시 검토할 수 있다.

원시 질문별 지표와 순위는 Git에서 제외된
`local_data/precedents/evaluation/hybrid_runs/precedent_bm25_hybrid_v01_90q/`
에 보관한다. 외부 API와 유료 호출은 사용하지 않았다.

## 한계

- BM25는 현재 판례 청크와 Kiwi 내용 형태소 설정 한 가지로 평가했다.
- RRF 입력은 Dense Top20과 BM25 Top20으로 고정했다. 더 큰 후보 깊이나 별도
  쿼리 확장은 이번 실험 범위에 포함하지 않았다.
- Recall은 승인 골든셋에 포함된 관련 판례를 기준으로 계산했다.
